==========================================================================
 GITHUB — solo daily workflow


   local  →  push `dev`  →  test on DEV server  →  PR  →  Squash merge `main`
==========================================================================


# =============================================================================
# EVERYDAY — push code from local to `dev`
# =============================================================================
# Do this every time you finish work and want it on the DEV server.

# 1) Be on `dev` and up to date
git checkout dev
git fetch origin
git pull origin dev

# 2) See what changed
git status
git diff

# 3) Commit
git add .
git commit -m "Short why (what this fixes / adds)"

# 4) Push to remote `dev`  ← this is what the DEV server uses
git push origin dev

# 5) Test on the DEV server
#    Redeploy / restart if needed — see commands/dev.txt
#    Click through the feature. Only go to main when it looks correct.


# =============================================================================
# WHEN DEV IS CORRECT — promote to `main` (not every day)
# =============================================================================
# Only after DEV server looks good.

# A) Create PR in GitHub UI
#   
#    base: main   ←   compare: dev
#    Create pull request

# B) Merge with **Squash and merge** (not "Create a merge commit")
#    → one clean commit on `main`

# C) Sync `dev` back to `main` (do this EVERY time after merge)
#    Fixes "1 ahead / 1 behind". Safe after a successful squash PR
#    when you have no extra uncommitted work still needed.
git checkout main
git pull origin main
git checkout dev
git reset --hard origin/main
git push --force-with-lease origin dev

# D) Next day — start again from EVERYDAY step 1


# =============================================================================
# ONE-TIME — GitHub repo settings (website)
# =============================================================================
# Settings → General → Pull Requests:
#   [x] Allow squash merging
#   [ ] Allow merge commits      ← leave OFF
#   [ ] Allow rebase merging     ← leave OFF
# Protect `main` (optional): require PR, no direct pushes


# =============================================================================
# DEV BROKE — roll back to last good (`main`)
# =============================================================================
# Optional: save WIP first
git stash push -u -m "broken wip"

git checkout dev
git fetch origin
git reset --hard origin/main
git push --force-with-lease origin dev
# Redeploy DEV — see commands/dev.txt

# Bring stash back later if needed:
#   git stash list
#   git stash pop


# =============================================================================
# BEFORE ANY RESET — don't lose uncommitted work
# =============================================================================
git stash push -u -m "wip before sync"
# ... reset / sync ...
git stash pop


# =============================================================================
# PUSH REJECTED
# =============================================================================
git fetch origin
git pull --rebase origin dev
# conflicts? → fix → git add <files> → git rebase --continue
git push origin dev

# Never:  git push --force
# OK after sync:  git push --force-with-lease origin dev


# =============================================================================
# CHECK STATE
# =============================================================================
git status
git branch -vv
git fetch origin
git rev-list --left-right --count origin/dev...origin/main
#   both numbers should be 0 after a sync
#   left  = on dev, not on main
#   right = on main, not on dev

git log --oneline --graph --decorate -12
git log --oneline origin/main..origin/dev



# =============================================================================
# CHEAT SHEET
# =============================================================================
# | When                | What                                              |
# |---------------------|---------------------------------------------------|
# | Everyday code       | checkout dev → commit → push origin dev → test    |
# | DEV looks good      | PR main←dev → Squash and merge                    |
# | Right after merge   | reset --hard origin/main → force-with-lease push  |
# | DEV broken          | same reset to main + redeploy                     |
# | Uncommitted WIP     | stash -u before reset; stash pop after            |


# =============================================================================
# DO NOT
# =============================================================================
# - Commit / push directly to `main`
# - Squash-merge then skip syncing `dev` (causes ahead/behind)
# - Use "Create a merge commit" on the PR
# - Open PR main → dev
# - `git push --force` (use `--force-with-lease` only after intentional sync)
# - `git reset --hard` while you still need uncommitted files (stash first)


# =============================================================================
# WHY "ahead / behind" happens
# =============================================================================
# Squash (or merge commit) creates a different tip on `main` than your
# old commits on `dev`. GitHub then shows ahead + behind.
# Fix: after every successful PR into `main`, reset `dev` to `origin/main`
# and push with --force-with-lease.
