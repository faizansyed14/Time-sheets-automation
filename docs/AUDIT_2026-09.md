## 1. PROJECT OVERVIEW

| Attribute | Value |
|---|---|
| Name | Timesheets Automation — "Timesheet Intelligence Portal" |
| Type | Internal web application + separate employee self-service portal, both served from one origin |
| Architecture | **Modular monolith.** One FastAPI process (async), one Celery worker with embedded beat (`-B`), one React SPA, nginx as the single gateway. Service-layer separation by domain package, no microservices, no serverless. |
| Backend | Python 3.13, FastAPI 0.116.1, SQLAlchemy 2.0.43 async ORM, Pydantic v2, Uvicorn |
| Frontend | TypeScript 5.6, React 18.3, Vite 5.4, TanStack Query v5, Tailwind 3.4, React Router 6 |
| Data | PostgreSQL (asyncpg) — the only supported DB; Redis for cache + Celery broker |
| Files | Pluggable vault: local filesystem, AWS S3, or OneDrive |
| Email | Microsoft Graph (application permissions) or a mock provider |
| AI | OpenAI-compatible chat/vision endpoint (OpenRouter in local dev), via LangChain |
| Deploy | Docker Compose on a single AWS EC2 host, me-central-1, behind nginx |

**Business purpose.** Employees' monthly timesheets arrive as email attachments or
portal uploads (xlsx / pdf / images / `.eml` / `.msg`). A two-pass vision LLM
classifies then extracts the leave grid. A human reviews in *Compare & Fix* and
presses **Accept**, which files a `timesheet_records` row and copies the source
document into a File Vault folder. Coverage roll-ups drive month-end chase-up
reminders.

**Entry points.**

| Process | Entry | Notes |
|---|---|---|
| API | `backend/app/main.py` | FastAPI app object, router registration, startup hooks |
| Worker + scheduler | `backend/app/services/tasks.py` via `backend/app/core/celery_app.py` | started with `-B`, so beat and worker share a container |
| SPA | `frontend/src/main.tsx` → `frontend/src/App.tsx` | React Router route table |
| Migrations | `backend/bootstrap_migrations.py`, `backend/alembic/env.py` | Alembic, 30 revisions |
| Gateway | `nginx/gateway.conf` | terminates the single published port |

| Helper | Rule | Lines |
|---|---|---|
| `get_current_user` | Bearer header **or** `?token=` / `?access_token=`; jti denylist; loads `User`; throttled `last_seen_at` commit | 43–76 |
| `require_user` | any authenticated | 79–80 |

### 4.1 Authentication (internal)

`routes/auth.py`, `services/auth/*`, `core/security.py`, `pages/Login.tsx`

Password check with bcrypt, then a short-lived `typ=login` token (TTL 10 min)
bound to a device fingerprint `fp`, then a second factor by per-user
`auth_mode`: `otp` (email code), `totp` (authenticator), or `captcha`.
Success issues a `typ=access` token carrying a random `jti`; logout adds the
`jti` to a Redis denylist.

| Route | Guard | Notes |
|---|---|---|
| `POST /auth/login` | public, rate-limited (user+IP) | routes to challenge; enqueues OTP mail |
| `POST /auth/verify-otp` / `verify-totp` / `verify-captcha` | public, rate-limited | issues access JWT |
| `POST /auth/resend-otp` | public, **not rate-limited** | mail spam vector |
| `GET /auth/captcha` | public, rate-limited per IP | returns PNG + `X-Captcha-Id` |
| `GET /auth/me` | `get_current_user` | may bump `last_seen_at` |
| `POST /auth/logout` | unauthenticated OK | revokes `jti`, clears `last_seen_at` |

Edge cases **handled:** OTP single-use, attempt and resend ceilings,
constant-time OTP compare (`otp.py:82`), constant-time CAPTCHA compare
(`captcha.py:77`), TOTP secret encrypted at rest with Fernet (`totp.py:21-26`),
client IP preferring `X-Real-IP` then the *last* `X-Forwarded-For` hop
(`auth.py:73-91`, which defeats naive first-hop spoofing **provided nginx
overwrites the header**).

Edge cases **missed:** resend has no limit; CAPTCHA verify is keyed on IP only
(`auth.py:282-284`) rather than IP+user; when Redis is down the cache silently
degrades to a per-process dict (`cache.py:95-106`), so with multiple uvicorn
workers the rate limits, OTP store and jti denylist stop being shared.

### 4.2 Authentication (employee portal)

`routes/portal_auth.py`, `pages/portal/PortalLogin.tsx`

Username + password only. **One factor, and no rate limiting**
(`portal_auth.py:52-56`) — the single largest asymmetry with the internal login,
across roughly 600 employee accounts.

### 4.3 Email inbox and thread extraction

`routes/inbox.py`, `services/inbox/*`, `services/extract_email/*`, `pages/Inbox.tsx`

Mail syncs from Microsoft Graph into `email_messages` via
PostgreSQL `ON CONFLICT DO UPDATE` that deliberately preserves workflow
`status` (`sync.py`), throttled behind a Redis lock. Reviewers open a thread and
press **Extract Email**, which runs the two-pass flow (§4.4) and stages
`PipelineFile` rows as `NEEDS_REVIEW`.

19 routes; the notable ones: `GET /inbox/{id}/llm-preview` renders the *exact*
payload that would be sent to the LLM without calling it — a genuinely good
egress-audit feature, though it exposes full prompt content to any full-access
user. `POST /inbox/{id}/decision` only supports the archive path; its
`accepted=True` branch always raises 400 (`inbox.py:841-846`), i.e. acceptance
is unreachable here by design and lives in the pipeline instead.

### 4.4 Two-pass extraction (the core of the product)

`services/extract_email/`, `services/extraction/`

| Step | Component | Gate | Can a bad value survive? |
|---|---|---|---|
| 1 | arrival (`upload.py`, portal, inbox) | roster grid rejected on single upload | **no byte cap** (`upload.py:61,93`) |
| 2 | `collect_thread_emls` | `max_thread_messages` = 40, tail slice | older sheets silently dropped (note only) |
| 3 | `collect_thread` | zip rejected, `MAX_EML_DEPTH=4`, page/pixel caps, dedupe | unsupported types still forwarded as a text placeholder (`thread_extract.py:575`) |
| 4 | PII prep | bodies + headers + document text scrubbed | **subject, filenames and all rendered JPEGs are not** |
| 5 | pass 1 triage | JSON parse + `_normalise_pass1_items` (kind enum, bool coercion) | `employee_name` / `employee_id` are unvalidated free strings |
| 6 | routing | multi-employee rosters diverted | — |
| 7 | pass 2 grid | month 1–12, year 2000–2100, period enum, int filters | pass 2 may **override** pass 1 identity (`thread_extract.py:861-864`); empty batch retried once |
| 8 | `grouping.group_sheets` | ISO date regex, cross-bucket conflict flags, calendar mismatch, `match_employee` | fold/sender heuristics (§10 L7) |
| 9 | `auto_accept.evaluate` | match + period + issues + coverage + approval | **recommend only, never files** |
| 10 | `staging.stage_groups` | idempotent by `thread_key` + employee tag | stages LLM buckets into `extraction_meta`, not yet a record |
| 11 | human **Accept** → `ingestion.py` | `validation.validate` | wrong employee if the reviewer accepts a bad match |

LLM calls are bounded: `vision_client.chat_call` uses `retries=3`, timeout from
`openai_timeout` (default 120s), `max_tokens=8000`, `temperature=0.0`. The chat
model uses `timeout=60, max_retries=1`. Roster grid calls are bounded by
`asyncio.Semaphore(4)`.

The **"nothing is filed without a human"** invariant holds: `auto_accept` only
produces a recommendation, and `stage_groups` only writes `NEEDS_REVIEW`. This
is the single most important design property in the codebase and it is intact.

### 4.6 Filing / ingestion

`services/pipeline/ingestion.py`

`ingest_manual_entry(employee_pk, month, year, buckets, source_key)`:

1. employee looked up by PK, **no `active` check** (258–260)
2. `_find_existing` loads **every record for that month/year** (213–214) then
   matches on `matched_employee_pk` → `employee_id`+exact name → **`employee_id`
   alone when the extracted name is empty** (228–229) → exact name
3. `_merge_source_files` replaces the entry with the same `source_key`, appends
   otherwise (174–178) — this is what makes re-Accept idempotent
4. `_union_buckets` unions dates per bucket; first file to claim a date wins;
   same-bucket collisions from different files raise an overlap **flag** rather
   than an error (192–206); public holidays and weekends are exempt
5. `validate` dedupes within a bucket and flags cross-bucket conflicts without
   removing them (`validation.py:96-122`)
6. vault write per attachment (325–334) — **no rollback if a later file fails**
7. bucket columns overwritten from the merged union (351–352); existing
   `account_manager` preserved (308–309)
8. single `db.commit()` (391)

### 4.7 Coverage, dashboard, export

`services/pipeline/coverage.py`, `routes/employees.py`, `routes/timesheets.py`,
`services/export/timesheet_export.py`

"Received" is defined once, in `received_subq(month, year)`, as any
`PipelineFile` whose `extraction_meta.staged.employee_pk` is non-null — **with no
status filter** (`coverage.py:39-46`). Dashboard coverage filters
`Employee.active.is_(True)`; the export grid does not (§10 L2).

### 4.8 Reminders

`services/reminders/*`, `routes/reminders.py` (all admin-only)

`missing_employee_pks` = active employees − (received ∪ filed). Scheduled send is
day 28, hour 9, `UAE_TZ` = fixed UTC+4 (`service.py:33-43`). Three independent
kill switches, all verified working:

1. `reminder_scheduled_check_enabled` — omits the beat entry (`celery_app.py:60-65`)
2. `ReminderConfig.auto_send_enabled` — DB toggle (`service.py:341-342`)
3. `reminder_sending_enabled` — checked inside the mailer (`mailer.py:55-59`), so
   it also covers **manual** *Send now* / *Test* / *Run batch*

Recipient resolution is work-email-first with personal fallback
(`service.py:52-72`) — correct. Idempotency is by "already ran today"
(`service.py:319-328`), which is a read-then-act check and therefore racy
between two workers (§10 L12).

### 4.9 Employee portal (self-service)

`routes/portal_employee.py`, `pages/portal/*`

Employees upload timesheet/approval files into named slots, then submit.
Ownership is enforced consistently through `_own_submission`
(`portal_employee.py:111-116`), which 404s when `employee_pk != user.employee_pk`.
**No cross-employee IDOR was found on any portal route** — this is the
best-guarded surface in the app.

### 4.10 File vault

`routes/files.py` (30 routes), `services/storage_provider/*`

Three-level structure `Manager / Name (ACO-…, DCO-…) / Month-Year /`.
Local reads/writes go through `local_provider._abs()`, which resolves and then
asserts `is_relative_to` the vault root (37–48) — **correctly contained**, and
covered by `tests/test_storage_path_safety.py`. S3 keys are sanitised via
`_safe()`. The `raw_store` and `portal_store` read paths do **not** have the same
containment (§10 S3).

### 4.11 Ask AI chat

`routes/agentic_chat.py`, `services/agents/chat_agent.py`, `pages/AgenticChat.tsx`

Generic streaming chat with **no DB tools and no DB access** — it cannot read
employee data unless a user uploads it. Attachment reads are capped at 20 MB
(`agentic_chat.py:74-91`), the only capped upload path in the codebase. Access is
governed by `ChatAccessConfig.enabled_for_others`, which the UI honours and the
`/stream` endpoint ignores (§10 S1).

| Field | Default | Risk |
|---|---|---|

### Production guards present

- `_assert_prod_secrets()` (`main.py:40-51`) refuses to boot when
  `is_prod` and the JWT secret is absent, under 32 chars, or contains
  `change-me`. Good, and the error message even prints the command to
  generate one.
- HSTS added when `is_prod` (`main.py:127-129`).

### Production guards missing

`_assert_prod_secrets` checks *only* the JWT secret. It does not reject
`AUTH_ENABLED=false`, the default admin password, `CELERY_TASK_ALWAYS_EAGER=true`,
`AUTO_CREATE_TABLES=true`, or `PII_REDACTION=false`. And `app = FastAPI(title=…,
lifespan=…)` (`main.py:86`) never disables docs, so **`/docs` and
`/openapi.json` are public in production**.

### Security headers — genuinely well done

`main.py:112-130` sets `X-Content-Type-Options: nosniff`, `Referrer-Policy:
no-referrer`, `Cross-Origin-Opener-Policy: same-origin`, a `Permissions-Policy`
denying geolocation/mic/camera, `X-Frame-Options: DENY` by default, and
downgrades to `SAMEORIGIN` + `frame-ancestors 'self'` only for preview paths
matched by `_EMBEDDABLE_PATH_MARKERS`. The comment block explaining why the
marker is `/content` and not `/files/content` is exactly the kind of comment
worth keeping.

`Referrer-Policy: no-referrer` **materially reduces** the `?token=` exposure in
§10 S2 — it stops cross-origin Referer leakage, though tokens still land in
browser history, nginx access logs and any intermediary.

### CORS

`main.py:88-95` — explicit origin list (never `*`), `allow_credentials=True`,
explicit method list, and headers narrowed to `Authorization`, `Content-Type`,
`X-Fingerprint`. Correct.

### `tsconfig.json`

`strict: true`, `noUnusedLocals`, `noUnusedParameters`, scoped to `src`. This is
the right configuration; the remaining type debt is manual `any` casts (§8).

### Linting

**No ESLint, no Prettier, no ruff/black/mypy, no pip-audit.** `tsc -b` in the
frontend build is the only automated static gate in the repository.

### Secrets

`.env` is **not tracked** and is correctly covered by `.gitignore` lines 9–12
(`.env`, `.env.*`, with `!.env.example` re-included). No hardcoded credential
was found in application source. The local `.env` does hold real OpenRouter and
Graph credentials, which is expected for a dev box but is precisely why the
sending kill switches matter (§10 S5).

## 6. SECURITY AUDIT

Ordered by severity. Full findings table in §10.

**Hardcoded secrets.** None in source. Two lower-grade issues: the default admin
credential pair lives in `config.py:238-239`, and
`seed/seed_test_employees.py:22-23` hardcodes **real personal email addresses**,
which is dangerous if that seeder is ever run against a DB with reminders
enabled.

**SQL injection.** None. Every query uses SQLAlchemy constructs or bound
parameters; the one raw SQL statement (migration `0014`'s `thread_key` backfill)
is a static string. Clean.

**XSS.** No `dangerouslySetInnerHTML` anywhere in `frontend/src`. Two real
vectors remain: the chat markdown renderer passes `href` straight through
(`AgenticChat.tsx:32-35`), and `sanitizeEmailHtml` blocks `javascript:` and
`vbscript:` but not `data:` or `blob:` (`filePreview.ts:132-137`), while the
email iframe is sandboxed with `allow-popups` (`Inbox.tsx:805`).

**CSRF.** Not applicable in the classic sense — auth is a `Authorization: Bearer`
header from localStorage, not a cookie, so there is no ambient credential to
ride. This is the one genuine security *advantage* of the localStorage choice.
Note that adopting cookie sessions (the fix for S2/S5) would **introduce** CSRF
exposure and require `SameSite` plus token protection.

**AuthN/AuthZ flaws.** Chat access unenforced server-side (S1); calendars and
portal-user management reachable by any full-access role (S6); portal login
unthrottled (S4); `AUTH_ENABLED=false` synthetic admin (S9). Internal
cross-object reads are by design — any full-access staff user may read any
record. Portal ownership checks are sound.

**Input validation.** Pydantic covers JSON bodies well. Weak spots are all at
trust boundaries with the LLM (unvalidated `employee_name` / `employee_id`
strings) and with the filesystem (`rel_path` in the debug image route).

**File upload handling.** Type detection is content-based rather than
extension-trusting in `file_processor.py`; zips are rejected in the thread
collector; `.eml`/`.msg` recursion is depth-capped at 4. The gap is size: only
the chat path caps bytes.

**Rate limiting.** Redis sliding window. Covers internal login, OTP verify, TOTP
verify, CAPTCHA issue and CAPTCHA verify. Does **not** cover portal login or OTP
resend, and silently degrades to per-process counters without Redis.

**Dependency CVEs.** No known-vulnerable version identified. `xlsx` 0.20.3 is
past CVE-2023-30533 and CVE-2024-22363. `PyMuPDF` is **AGPL-3.0** — a licence
question rather than a vulnerability, but one that should be answered
deliberately.

## 7. PERFORMANCE AUDIT

**N+1 queries.** `Dashboard.tsx:168-182` mounts a `ViewRecordButton` per
coverage row, each with its own `useQuery(["employee-records", pk, year])` — a
50-row month means 50 requests.

**Whole tables loaded into Python.**

| Location | What |
|---|---|
| `pipeline.py:145` | entire `pipeline_files` table for `/pipeline/stats` |
| `employees.py:276-279` | entire `timesheet_records` table for the `unmatched::` view |
| `ingestion.py:213-214` | every record for the month, on **every** Accept |
| `files.py:260-264` | every employee, per manager-folder resolution |
| `matching.py:163`, `rematch.py:38`, `roster_stage.py:95`, `import_service.py:447` | full employee table (correct for a global fuzzy scan, but should at least be `active`-filtered) |

**Missing pagination.** `GET /timesheets`, `GET /pipeline/portal-submissions`.

**Blocking / DoS.** Unbounded `await file.read()` on every upload path except
chat, against an nginx body limit that is far larger than a timesheet ever is.
`CELERY_TASK_ALWAYS_EAGER=True` by default means a mis-set prod env makes
120-second LLM extractions run **inside** the API worker.

**Frontend.** Polling at 15 s on Shell stats, Pipeline and Inbox with no
`document.visibilityState` gate, so idle tabs keep working. The global reload
button calls `qc.invalidateQueries()` with no filter (`Shell.tsx:121-127`),
refetching the entire cache. `xlsx` and `exceljs` are at least **lazily**
imported in `XlsxPreview.tsx`, so they do not weigh on initial load.

**Memory leaks.** `streaming.py:35-36` keeps a module-level `_background_tasks`
set for detached SSE extractions; `sheet_cache` grows the `extracted_sheets` JSON
blob on `email_messages` without a cap; captcha blob URLs are never revoked
(`Login.tsx:105`).

**Caching done well.** `core/datacache.py` provides versioned namespace
memoisation with explicit busting, used consistently across pipeline, coverage
and employee reads. Roster extraction caches by content hash for 15 minutes.
Incremental extraction reuses prior sheet reads by digest — effective, but
without a prompt-version key, so a prompt fix does not invalidate it.

## 8. CODE QUALITY & MAINTAINABILITY

**Comment quality is the standout strength.** Comments explain *why*, not what —
for example `employee.py:57-59` on why `work_email` and `personal_email` must
never be merged, and `main.py:97-104` on the CSP path-marker choice. This is
better than most production codebases.

The flip side is that several comments have drifted out of true, and because the
comments are trusted, drift is actively harmful:

| Location | Claims | Reality |
|---|---|---|
| `employee.py:62-64` | inactive rows "excluded from matching going forward" | no matcher query filters `active` |
| `vision_client.py:14` | "Prompts are PII-scrubbed before every call" | only the system prompt is scrubbed |
| `sheet_cache.py:3-7` | "Every run re-reads every attachment" | digests are reused |
| `crypto.py:1-6` | describes `app_config` encryption | that table was dropped in `0013`; the module is now used for TOTP secrets |
| `rematch.py:4-5` | matching runs once at staging | this module re-runs it |
| `orchestrator/base.py:8-9` | a separate Approval agent calls the LLM | approval is derived in `thread_extract._derive_approval` |

**DRY violations.** `_review_state` is implemented twice
(`portal_employee.py:71-90` and `pipeline.py:206-213`) — same rules, two places
to change. "Missing" is computed by two different definitions
(`employees.py:99-114` vs `service.missing_employee_pks`), which
`reminders.py:115-119` documents as intentional; intentional or not, two
definitions of the central business metric is a liability.

**Type safety.** Backend is fully annotated but **unchecked** — no mypy. Frontend
is `strict` with real debt: `onError: (e: any)` throughout, `(rec as any)` for
dynamic bucket keys in `Record.tsx`, `Promise<any>` from `streamExtraction`.

**Error handling.** Mostly explicit. The bad pattern is bare
`except Exception: pass` around boot-critical work (`main.py:67-69,74-76,80-82`)
— legacy relocation, raw purge and **admin seeding** can all fail invisibly. Also
`crypto.py:33-34` catches everything and returns `""`, turning a decrypt failure
into an empty TOTP secret, and `orchestrator.py:52-57` logs and continues past a
failed agent, producing partial pipeline state that looks successful.

**Test coverage.** ~55 pytest modules covering extraction, auth/OTP, vault path
safety, portal auth and submissions, matching, reminders, S3, and end-to-end
pipeline. Genuinely strong for a project with no CI. Notable gaps: **no test
asserts that matching excludes inactive employees** (the §10 L1 bug class), and
the frontend has **zero** tests.

**Documentation.** `docs/` is unusually thorough (2,040 lines). Accuracy is the
problem — see §10 D-series.
